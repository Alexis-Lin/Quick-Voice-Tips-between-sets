## 三个技术问题的简答

### Q2 · 撒花动画怎么写
- **(a) 语言**：**C**（嵌入式）。直接写 RGB565 framebuffer，或挂到 LVGL 定时器里绘制。手机端用各自原生（Swift/Kotlin），**算法完全相同**。
- **(b) 嵌入式可播**：**可以**。粒子系统是最省的动画之一——几百个小方块，RGB565 + 定点运算，30fps 在中端 MCU 轻松跑。
- **(c) 高性能 / 无素材**：**纯代码粒子系统**，粒子是"画"出来的小矩形，零图片资源；固定粒子池、无 malloc、圆形裁剪就绪。实现见 [`03-confetti.c`](./03-confetti.c)。
  - 提速开关：关闭 alpha 混合直接写色 / 降 30fps / 定点整数 / 限制粒子数。

### Q3 · 语音怎么"提前生成"又贴合
- **预生成、不实时 TTS**：语音离线批量生成成音频，运行时只"挑一条+播放"，延时≈0。
- **贴合但不过度依赖**：只依赖**粗粒度完成桶**（范围×状态×表现，完成瞬间已知），**不把精确次数烧进语音**（次数交给 UI 呈现）。
- **多样性**：每桶预生成 8~15 条较长文案，洗牌袋挑选防重复。详见 [`04-voice-copy.md`](./04-voice-copy.md)。

### Q4 · 独立原子模块（不拥有导航）
- 庆祝界面是**自包含原子模块**：只负责把这一次庆祝演完（UI+撒花+音效+预生成语音）。
- **不决定去向**：演完发 `onDone`，去哪儿（休息/结课数据/退出）由**当时业务逻辑**决定。
- 停留时长可由宿主 `dwellMs` 控制或完全接管生命周期。详见 [`05-atomic-module.md`](./05-atomic-module.md)。
